# Session و تعارض اتصال

- برای هر session فقط یک اتصال زنده مجاز است.
- پیش از ساخت یا بازکردن اتصال جدید، اتصال قبلی همان session باید بسته شود.
- برای هر تلاش ورود `attempt_id` تصادفی ساخته شود و context فقط با شماره کلید نخورد.
- دو نمونه هم‌زمان از master یا یک service اجرا نشوند؛ پس از تغییر نسخه فقط یک نمونه `rubika-master` فعال باشد.
- مسیر پورتال نباید با بستن اتصال، job فعال اکانت ثبت‌شده را قطع کند.
- حذف اکانت فقط با خطای قطعی authentication نامعتبر مجاز است.
- timeout، قطعی شبکه، `Worker unavailable` و `FloodWait` خطای موقت‌اند و نباید باعث حذف اکانت شوند.
- پیش از حذف قطعی، jobهای اکانت متوقف و اتصال آن بسته شود؛ سپس account، session و تنظیمات یا اتوماسیون‌های وابسته پاک شوند.
