ترتیب آینده مصوب:

1. backup، ثبت rollback commit و MD5 هسته
2. اصلاح lifecycle پورتال و Custom Domain
3. ساخت storage و event model پورتال
4. پیاده‌سازی `attempt_id` و cleanup پنج‌دقیقه‌ای
5. اتصال UI تأییدشده به API واقعی
6. آمار، پنل پورتال و کارت خلاصه `/start`
7. کارت‌های گزارش کامل
8. ناظر محدود برای وضعیت پورتال و حذف session نامعتبر قطعی
9. متن خودکار پس از ورود با sender موجود
10. ارسال چنداکانتی تلگرام با صف مشترک، failover، cooldown و checkpoint
11. تست failure، concurrency و restart؛ سپس syntax check و کنترل MD5 هسته
12. push روی شاخه جدید، PR به `production` و deployment امن پس از merge

# پلن ثبت‌شده (ساخته نشده) — مخفی‌کردن فرستنده در فوروارد

> ثبت: ۲۰۲۶-۱۱-۰۵ · درخواست مالک · **هنوز پیاده نشده، فقط پلن**
> قاعده‌ی مهم مالک: **کد فوروارد حذف نشود.** اگر این روش جواب نداد یا روی
> ارسال اثر بد گذاشت، باید بتوانیم سریع به حالت قبل برگردیم.

## مسئله

ارسال فعلی با `rb.forward_message()` از Saved Messages انجام می‌شود. فوروارد
بالای پیام برچسب «Forwarded from …» می‌زند، پس گیرنده می‌فهمد پیام دست‌به‌دست
شده و شخصی نیست.

## راه‌حل اصلی (کم‌ریسک‌ترین): تنظیم حریم خصوصیِ خود روبیکا

روبیکا معادل تنظیم «Forwarded Messages» تلگرام را دارد. در خروجی واقعی
`getPrivacySetting` روی اکانت مالک این مقدار دیده شد:

```json
"link_forward_message": "Everybody"
```

تغییرش با endpoint `setSetting`:

```python
await client.builder(name="setSetting", input={
    "settings": {"link_forward_message": "Nobody"},
    "update_parameters": ["link_forward_message"],
})
```

**چرا این گزینه بهترین است:** یک تنظیمِ سطح‌اکانت است، پس **هیچ خطی از مسیر
ارسال / فوروارد / مغز / کانال / انتقال ورکر عوض نمی‌شود.** برگشتش هم فقط
ست‌کردن دوباره‌ی `Everybody` است.

### ⚠️ انتظارِ واقع‌بینانه (تأیید نشده)
در تلگرام این تنظیم نام فرستنده را **بدون لینک** می‌کند، نه اینکه کل برچسب
فوروارد را حذف کند. اینکه روبیکا برچسب را کامل بردارد یا فقط لینک را، **بدون
تست روی اکانت واقعی قابل‌ادعا نیست**. پس اول باید تست شود، بعد قضاوت.

## راه‌حل جایگزین (اگر راه اول برچسب را کامل برنداشت): ارسال کپی

به‌جای فوروارد، یک **پیام نو** ساخته شود با همان فایلِ قبلاً آپلودشده:

1. پیام مارکر در Saved Messages یک بار خوانده شود → `file_inline` + کپشن
2. برای هر مخاطب: `send_message(guid, text=caption, file_inline=<همان ارجاع>)`

امضای rubpy این را پشتیبانی می‌کند:
`file_inline: Optional[Union[Update, Path, bytes]]` — یک آبجکت پیام را هم
قبول می‌کند، پس فایل **دوباره آپلود نمی‌شود** (ارجاع همان فایل روی سرور
روبیکا است) و برچسب فوروارد هم نمی‌خورد.

**ریسکش بیشتر است** چون مسیر ارسال را لمس می‌کند، پس فقط اگر راه اول کافی
نبود. و در آن حالت هم باید به‌عنوان یک **شیوه‌ی ارسالِ جداگانه** اضافه شود،
نه جایگزینِ فوروارد.

## پلن پیاده‌سازی (به ترتیب)

1. **پروبِ فقط-خواندنی:** `getPrivacySetting` روی هر سه اکانت تا مقدار فعلی
   `link_forward_message` ثبت شود (برای برگشت‌پذیری).
2. **ماژول ایزوله** (الگوی `send_order.py` / `caption_file.py`): تابع
   set/get برای این تنظیم + تأیید با خواندنِ دوباره‌ی `getPrivacySetting`
   (نه اعتماد به پاسخِ خالیِ setSetting).
3. **دکمه در ⚙️ ستینگ:** «🫥 مخفی‌کردن فرستنده در فوروارد» با وضعیت
   ON/OFF و اعمال روی یک اکانت یا همه. برگشت با همان دکمه.
4. **کارت لاگ:** موفق/ناموفق به‌ازای هر اکانت، با مقدار قبلی و بعدی.
5. **تست یک‌پیامی** به شماره‌ی تست، و دیدن اینکه برچسب فوروارد سمت گیرنده
   واقعاً رفته یا نه. **تا این تأیید نشود، فیچر «کار می‌کند» اعلام نشود.**
6. اگر کافی نبود → راه‌حل جایگزین (ارسال کپی) به‌عنوان شیوه‌ی چهارم.

## چیزهایی که در این کار دست نمی‌خورند
`rb.forward_message` و همه‌ی صداکننده‌هایش، مسیر مارکر، مغز، مغز کانال،
مغز استخری، انتقال ورکر، و فایل‌های pinned (`core/`, `rubika_client.py`,
`worker.py`, `main.py`, `config.py`, `portal/`).
